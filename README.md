## 📖 درباره پروژه

نرم‌افزار مدیریت انبار **کارخانه قند صنوبر** (شرکت صنایع غذایی سایه سار صنوبر آریا) یک **Progressive Web App** تک‌فایلی است که به‌صورت کامل روی مرورگر اجرا می‌شود و نیازی به سرور اختصاصی ندارد.

داده‌ها به‌صورت **آفلاین** در حافظه مرورگر نگهداری می‌شوند و با استفاده از **GitHub API** روی مخزن کاربر همگام‌سازی می‌شوند.

### ✨ ویژگی‌های اصلی

- 🖥️ **اجرا روی هر مرورگری** — بدون نیاز به نصب
- 📴 **کار در حالت آفلاین** — داده‌ها در localStorage ذخیره می‌شوند
- ☁️ **همگام‌سازی چند دستگاهی** — با GitHub Contents API
- 📅 **تقویم جلالی** با پیاده‌سازی داخلی
- 🔢 **اعداد فارسی** در تمام رابط کاربری
- 🌙 **حالت شب** با ذخیره تنظیمات
- 🖨️ **گزارش‌گیری حرفه‌ای** (A4/A5 - پرتره/افقی)
- 📊 **خروجی CSV** برای اکسل
- 🔐 **مدیریت هوشمند حذف** با Tombstone
- 🧹 **پاک‌سازی دستی دیتابیس** با محافظت Epoch
- ⚡ **سبک و سریع** — فایل نهایی حدود ۱۵۰ کیلوبایت

## 🆕 چه چیزی در نسخه ۳.۴.۰ جدید است؟

### 🔄 ساختار داده v6

فایل داده از `data.json` به `data-v6.json` منتقل شده است. این کار مزایای زیر را دارد:

- ✅ **کاهش حجم تا ۷۰٪** — کوتاه کردن کلیدها و استفاده از ID
- ✅ **جلوگیری از برگشت داده‌های حذف‌شده** — با Tombstone
- ✅ **جلوگیری از تداخل نسخه‌ها** — دستگاه قدیمی نمی‌تواند داده جدید را خراب کند
- ✅ **محافظت Epoch** — جلوگیری از برگشت بعد از پاک‌سازی کامل

### 🗑️ تب جدید «رکوردهای حذف‌شده»

- تب جداگانه زیر سوابق ورود/خروج
- پیش‌فرض بسته و پنهان
- مرتب‌سازی بر اساس تاریخ حذف (جدیدترین اول)
- ستون «نوع» (ورود/خروج) و «حذف‌شده در»
- بازگردانی یا حذف کامل هر رکورد

### 🧹 پاک‌سازی هوشمند دیتابیس

- پاک کردن رکوردهای حذف‌شده + Tombstoneها به‌صورت دستی
- با محافظت `epoch` — از برگشت داده‌های قدیمی جلوگیری می‌کند
- فقط زمانی که همه کاربران آفلاین هستند

## 🚀 راه‌اندازی سریع

### پیش‌نیازها

- یک مرورگر مدرن (Chrome، Firefox، Edge، Safari)
- یک حساب [GitHub](https://github.com) رایگان
- فایل `converter.html` برای تبدیل دیتای قدیم (اختیاری — فقط برای بار اول)

### گام ۱ — Fork کردن مخزن

روی دکمه **Fork** در بالای صفحه کلیک کنید یا مخزن را Clone کنید.

### گام ۲ — فعال‌سازی GitHub Pages

1. به **Settings → Pages** بروید
2. در قسمت **Source** گزینه `Deploy from a branch` را انتخاب کنید
3. Branch را روی `main` و پوشه را روی `/root` تنظیم کنید
4. روی **Save** کلیک کنید
5. چند دقیقه صبر کنید تا سایت بالا بیاید

آدرس سایت شما: `https://USERNAME.github.io/REPOSITORY/`

### گام ۳ — ساخت Personal Access Token

1. به [GitHub Settings → Tokens](https://github.com/settings/tokens) بروید
2. روی **Generate new token (classic)** کلیک کنید
3. نام دلخواه وارد کنید (مثل `Warehouse Sync`)
4. در بخش **Scopes**، گزینه `repo` را انتخاب کنید
5. روی **Generate token** کلیک کنید
6. **توکن را کپی کنید** (فقط یک بار نمایش داده می‌شود)

### گام ۴ — تبدیل داده قدیم (فقط بار اول)

اگر از نسخه قدیمی مهاجرت می‌کنید:

1. فایل `data.json` را از GitHub دانلود کنید
2. فایل `converter.html` را در مرورگر باز کنید
3. فایل `data.json` را آپلود کنید
4. روی **💾 دانلود data-v6.json** کلیک کنید
5. فایل `data-v6.json` را روی GitHub آپلود کنید

### گام ۵ — اتصال برنامه

1. سایت را باز کنید
2. روی آیکون **☰** (تنظیمات) کلیک کنید
3. بخش **☁️ اتصال GitHub** را باز کنید
4. اطلاعات زیر را وارد کنید:
   - **Username**: نام کاربری GitHub
   - **Repository**: نام مخزن (مثلاً `Warehouse`)
   - **Token**: توکن ساخته‌شده
5. روی **💾 ذخیره و تست اتصال** کلیک کنید

✅ اگر پیام **دسترسی کامل** را دیدید، همه چیز آماده است!

## 📚 راهنمای استفاده

### ثبت ورود کالا

1. روی دکمه **📥 ورود کالا** کلیک کنید
2. فرم باز می‌شود — فیلدها را پر کنید:
   - **تاریخ و ساعت** (خودکار = الان)
   - **کالا** (از لیست یا `+` برای جدید)
   - **زیرمجموعه** (اختیاری)
   - **تعداد و واحد**
   - **مجموع وزنی** (خودکار محاسبه می‌شود)
   - **فروشنده و راننده**
   - **شماره فاکتور، باسکول، بارنامه**
   - **توضیحات**
3. روی **💾 ثبت اطلاعات** کلیک کنید

### ثبت خروج کالا

مثل ورود است، فقط دکمه **📤 خروج کالا** را انتخاب کنید و فیلد **خریدار** جایگزین فروشنده می‌شود.

### همگام‌سازی

- **⬇️ دریافت**: داده‌ها را از GitHub می‌خواند
- **⬆️ ذخیره**: تغییرات را روی GitHub می‌نویسد

> 💡 **نکته مهم**: اگر تغییرات ذخیره‌نشده دارید و دکمه «دریافت» را بزنید، پیام هشدار می‌گیرید.

### مشاهده رکوردهای حذف‌شده

1. به بخش **سوابق ثبت شده** بروید
2. تب **🗑️ رکوردهای حذف‌شده** را باز کنید
3. می‌توانید:
   - **🔄** رکورد را بازگردانی کنید
   - **🗑️** رکورد را برای همیشه حذف کنید

### گزارش‌گیری

- **📅 خلاصه روزانه**: ماتریس تاریخ × کالا (وزنی/شمارشی)
- **🖨️ گزارش کامل**: جدول کامل با جمع کل
- **📊 CSV**: خروجی برای Excel
- **👁️ مشاهده رسید**: پیش‌نمایش A5 برای چاپ

## 🗂️ ساختار داده (v6)

داده‌ها در فایل `data-v6.json` روی مخزن GitHub ذخیره می‌شوند:

```json
{
  "v": 6,
  "epoch": 1,
  "ts": "2026-01-15T10:30:00.000Z",
  "by": "نام کاربر",
  "units":    [{"i":1, "c":"kg", "n":"کیلوگرم", "f":1}],
  "products": [{"i":1, "n":"شکر", "u":1, "s":["کوهرنگ"]}],
  "sellers":  [{"i":1, "n":"شرکت الف"}],
  "buyers":   [{"i":1, "n":"شرکت ب"}],
  "drivers":  [{"i":1, "n":"احمدی"}],
  "records":  [
    {
      "i": 1704067200000,
      "t": 0,
      "d": "1404/07/15",
      "h": "10:30",
      "p": 1,
      "st": "کوهرنگ",
      "q": "100",
      "u": 1,
      "w": "100",
      "a": 1,
      "v": 1,
      "n": "14040715-001",
      "m": 1704067200000
    }
  ],
  "del": [],
  "tomb": {"p":[], "s":[], "b":[], "d":[], "u":[]}
}
```

### نقشه کلیدها

| کلید | مفهوم | کلید | مفهوم |
|---|---|---|---|
| `i` | id | `p` | product (ID) |
| `t` | type (0=ورود، 1=خروج) | `st` | subtype |
| `d` | date | `a` | party (ID) |
| `h` | time (ساعت) | `v` | driver (ID) |
| `q` | quantity | `n` | invoice |
| `u` | unit (ID) | `b` | basil |
| `w` | weight | `y` | waybill |
| `m` | updatedAt | `c` | notes |
| `x` | deleted (1=حذف) | `del` | permanentlyDeletedIds |
| `tomb` | لیست‌های حذف‌شده | `epoch` | نسل دیتابیس |

**مزایای این ساختار:**
- 🎯 کاهش حجم تا **۷۰٪**
- ⚡ merge سریع‌تر
- 🧹 تغییر نام کالا بدون آپدیت رکوردها
- 🔒 جلوگیری از برگشت داده‌های حذف‌شده

## 🗑️ مکانیزم حذف

سیستم سه سطح حذف دارد:

### ۱. حذف نرم (Soft Delete)
رکورد با `deleted: true` علامت می‌خورد. در تب **🗑️ رکوردهای حذف‌شده** نمایش داده می‌شود.

### ۲. Tombstone (لیست سیاه)
برای لیست‌ها (کالا، فروشنده، خریدار، راننده، واحد) استفاده می‌شود. از برگشت آیتم حذف‌شده در همگام‌سازی جلوگیری می‌کند.

### ۳. پاک‌سازی کامل دیتابیس
🧹 **دستی** — زمانی که مطمئنید هیچ کاربری متصل نیست:
- همه رکوردهای حذف‌شده برای همیشه پاک می‌شوند
- لیست Tombstoneها خالی می‌شوند
- `epoch` یک واحد افزایش می‌یابد
- فایل GitHub کامل بازنویسی می‌شود

> ⚠️ **قبل از پاک‌سازی کامل**: همه کاربران باید تغییراتشان را ذخیره کرده و آفلاین شوند.

### ۴. محافظ Epoch

هر بار که پاک‌سازی کامل انجام می‌شود، `epoch` یک واحد افزایش می‌یابد. اگر کاربری با `epoch` قدیمی بخواهد push کند:

1. پیام هشدار می‌بیند: «دیتابیس بازنشانی شده»
2. Push متوقف می‌شود
3. کاربر باید ابتدا pull کند و سپس تغییرات جدید اعمال کند

## 🔄 راهنمای مهاجرت از v5 به v6

### برای کاربران تک‌نفره

1. بکاپ فایلی بگیرید (`📁 پشتیبان فایلی → 💾 پشتیبان‌گیری`)
2. `data.json` را از GitHub دانلود کنید
3. با `converter.html` به `data-v6.json` تبدیل کنید
4. `data-v6.json` را روی GitHub آپلود کنید
5. `index.html` را به v3.4.0 آپدیت کنید
6. `Ctrl+F5` بزنید و Pull کنید
7. پس از تأیید، `data.json` را حذف کنید

### برای کاربران چندنفره

**قبل از شروع به همه اطلاع دهید:**

> ⚠️ فردا آپدیت می‌کنیم — لطفاً امشب کارتان را تمام کنید و Push کنید.

**ترتیب دقیق:**

1. همه کاربران Push نهایی می‌زنند
2. همه صفحه را می‌بندند
3. مسئول: `data.json` را دانلود و بکاپ می‌گیرد
4. مسئول: با converter به `data-v6.json` تبدیل می‌کند
5. مسئول: `data-v6.json` را روی GitHub آپلود می‌کند
6. مسئول: `index.html` را به v3.4.0 آپدیت می‌کند
7. مسئول: خودش اول Pull می‌کند و چک می‌کند
8. مسئول به همه اطلاع می‌دهد: «آپدیت شد — `Ctrl+F5` بزنید»
9. همه کاربران: `Ctrl+F5` + Pull
10. پس از تأیید همه: مسئول `data.json` را حذف می‌کند
