## 📂 ساختار فایل‌ها

پوشه پروژه باید اینطوری باشه:

```
Warehouse/
├── index.html          ← فایل اصلی برنامه
├── manifest.json       ← معرفی PWA (اسم، آیکن، رنگ)
├── sw.js               ← Service Worker (کش و آفلاین)
├── icon-192.png        ← آیکون کوچیک (192×192)
├── icon-512.png        ← آیکون بزرگ (512×512)
├── .gitattributes      ← تنظیم UTF-8 برای Git
└── README.md           ← همین فایل
```

> ⚠️ **مهم:** هر ۶ فایل بالا باید کنار هم توی ریشه مخزن `Warehouse` باشن.

## 🌐 استقرار روی GitHub Pages

### گام ۱ — ساخت Repository

1. وارد [github.com](https://github.com) شوید
2. روی **New repository** کلیک کنید
3. نام: `Warehouse`
4. **Private** یا Public — فرقی ندارد
5. ✅ گزینه **Add a README file** را تیک بزنید
6. **Create repository**

### گام ۲ — آپلود فایل‌ها

1. توی مخزن `Warehouse` → **Add file** → **Upload files**
2. این فایل‌ها رو بکش و رها کن:
   - `index.html`
   - `manifest.json`
   - `sw.js`
   - `icon-192.png`
   - `icon-512.png`
3. **Commit changes**

### گام ۳ — فایل `.gitattributes`

توی مخزن → **Add file** → **Create new file**
اسم فایل: `.gitattributes`

محتوا:
```
* text=auto eol=lf
*.html text working-tree-encoding=UTF-8
*.js   text working-tree-encoding=UTF-8
*.css  text working-tree-encoding=UTF-8
*.json text working-tree-encoding=UTF-8
*.md   text working-tree-encoding=UTF-8
```

Commit کن.

### گام ۴ — فعال‌سازی GitHub Pages

1. **Settings** → **Pages**
2. **Source** → **Deploy from a branch**
3. **Branch** → `main` → `/ (root)`
4. **Save**
5. صبر کن ۱ تا ۲ دقیقه

لینک نهایی:
```
https://[username].github.io/Warehouse/
```

مثال برای این پروژه:
```
https://ghandsenobar.github.io/Warehouse/
```

## 📱 نصب روی موبایل (PWA)

بعد از اینکه لینک بالا کار کرد:

### اندروید (Chrome)

1. لینک رو باز کن
2. پایین صفحه پیام **«Add to Home screen»** میاد → بزن
3. یا از منوی ⋮ → **Install app**
4. آیکن روی صفحه اصلی میاد ✅

### iOS (Safari)

1. لینک رو باز کن
2. دکمه **Share** (مربع با فلش)
3. **Add to Home Screen** → **Add**

### دسکتاپ (Chrome / Edge)

توی نوار آدرس، آیکن **⊕ نصب** ظاهر میشه → کلیک کن → مثل یه اپ جدا باز میشه.

### مزایای PWA

| ویژگی | توضیح |
|---|---|
| 📱 نصب راحت | یه بار از لینک نصب، همیشه از آیکن باز کن |
| ⚡ لود سریع | فایل‌ها کش می‌شن → زیر ۱ ثانیه |
| 🌐 آفلاین | نت قطع باشه هم باز میشه |
| 🔄 آپدیت خودکار | نسخه جدید خودکار لود میشه |

## ☁️ تنظیمات GitHub Sync

### گام ۱ — ساخت Personal Access Token

1. **Settings** → **Developer settings** → **Personal access tokens** → **Fine-grained tokens**
2. **Generate new token**
3. تنظیمات:
   - **Name:** `Warehouse Token`
   - **Expiration:** مثلاً 1 year
   - **Repository access:** فقط مخزن `Warehouse`
   - **Repository permissions** → **Contents: Read and write** ✅
4. **Generate token**
5. توکن (`github_pat_...`) رو **کپی** کن

> ⚠️ این توکن فقط **یک بار** نمایش داده میشه — ذخیره‌اش کن

### گام ۲ — وارد کردن در برنامه

از منوی ☰ → **☁️ اتصال GitHub**:

| فیلد | مقدار |
|---|---|
| GitHub Username | نام کاربری گیت‌هاب |
| Repository Name | `Warehouse` |
| Personal Access Token | توکن کپی‌شده |

**💾 ذخیره و تست اتصال** رو بزن.

### گام ۳ — استفاده

- **⬇️ دریافت:** اطلاعات از GitHub به مرورگر می‌آید
- **⬆️ ذخیره:** اطلاعات مرورگر به GitHub می‌رود

**نوار وضعیت:**
- 🟢 همه چیز ذخیره شده
- 🟠 تغییرات ذخیره‌نشده
- 🔒 توکن فقط خواندنی
- ❌ خطا در اتصال
- ⚪ تنظیمات وارد نشده

## 🔐 پسورد بخش پشتیبان

بخش **«📁 پشتیبان فایلی»** با پسورد محافظت می‌شود.

### پسورد پیش‌فرض

```
#Aa09151217270
```

### نحوه کار

1. روی هدر **«📁 پشتیبان فایلی»** کلیک کن
2. مودال پسورد باز می‌شود
3. پسورد رو وارد کن
4. **۳ بار** اشتباه = دسترسی رد می‌شود
5. پس از ورود موفق:
   - آیکن 🔓 نمایش داده می‌شود
   - دکمه **🔒 قفل کردن** در هدر ظاهر می‌شود
6. با **بستن تب** یا **دکمه 🔒** مجدداً قفل می‌شود

### چرا این پسورد؟

- جلوی **کاربر عادی انبار** را می‌گیرد
- برنامه پسورد را به‌صورت **Base64** ذخیره می‌کند (نه متن ساده)
- کاربر فنی با DevTools می‌تواند دور بزند — این لایه **UX** است نه امنیت واقعی

## 📦 مدیریت کالا و واحد

### افزودن کالا

از منوی ☰ → **📦 کالاها و زیرمجموعه‌ها** → **➕ افزودن کالای جدید**

فرم شامل:
1. **نام کالا** (مثلاً: شکر)
2. **واحد پیش‌فرض** (شماره واحد)
3. **زیرمجموعه‌ها** (اختیاری — با کاما جدا)

مثال: کالای «شکر» با زیرمجموعه‌های «کوهرنگ, اصفهان, صنوبر»

### افزودن واحد

از منوی ☰ → **📏 واحدهای اندازه‌گیری** → **➕ افزودن واحد جدید**

| فیلد | توضیح |
|---|---|
| کد واحد | `kg`, `pcs`, `ton` |
| نام نمایشی | «کیلوگرم»، «عدد» |
| ضریب تبدیل | مقدار کیلوگرم معادل ۱ واحد |

**مثال ضریب‌ها:**
- کیلوگرم: `1`
- گرم: `0.001`
- تن: `1000`
- کارتن: خالی بگذارید

### افزودن سریع از فرم

داخل فرم ثبت، کنار هر فیلد دکمه **➕**:
- کنار کالا → افزودن کالا
- کنار واحد → افزودن واحد
- کنار طرف حساب → افزودن فروشنده/خریدار
- کنار راننده → افزودن راننده

## 🔄 آپدیت نسخه PWA

وقتی `index.html` رو تغییر دادی و روی GitHub آپلود کردی، کاربرا **خودکار** آپدیت نمی‌شن چون Service Worker قدیمی کش رو نگه می‌داره.

### راه‌حل: تغییر شماره نسخه

توی `sw.js`، این خط رو پیدا کن:

```javascript
const CACHE_NAME = 'senobar-warehouse-v1';
```

بعد از هر آپدیت، عدد رو **+1** کن:

```javascript
const CACHE_NAME = 'senobar-warehouse-v2';  // ← عدد رو عوض کن
```

با این کار:
- Service Worker قدیمی حذف می‌شه
- کاربرا بار بعد که اپ رو باز کنن، نسخه جدید رو می‌بینن

> ⚠️ اگه شماره رو عوض نکنی، کاربرا نسخه قدیمی رو می‌بینن!

## 🔤 نکات Encoding

### چرا مهمه؟

اگه فایل HTML با کدگذاری اشتباه (ANSI) ذخیره بشه، ایموجی‌ها و کاراکترهای فارسی **خراب می‌شن** (مثل `7�1`).

### ✅ روش درست ذخیره

**در Notepad:**
1. **File** → **Save As**
2. **Encoding** → **UTF-8** (نه UTF-8 with BOM، نه ANSI)
3. ذخیره

**در VS Code:**
1. پایین-راست → روی **UTF-8** کلیک
2. **Save with Encoding** → **UTF-8**

### فایل `.gitattributes`

این فایل به Git می‌گه همه فایل‌های متنی UTF-8 هستن:

```
* text=auto eol=lf
*.html text working-tree-encoding=UTF-8
*.js   text working-tree-encoding=UTF-8
*.css  text working-tree-encoding=UTF-8
*.json text working-tree-encoding=UTF-8
*.md   text working-tree-encoding=UTF-8
```

> ⚠️ اسم فایل باید دقیقاً `.gitattributes` باشه — با نقطه اول و **بدون پسوند**.

### چک‌لیست قبل از آپلود

```
☐ فایل با UTF-8 ذخیره شده
☐ توی مرورگر محلی تست شد
☐ توی GitHub آپلود شد
☐ توی گوشی چک شد
```

## 🔧 عیب‌یابی

### ❌ ایموجی‌ها خراب شدن (`7�1`)

**علت:** فایل با ANSI ذخیره شده یا GitHub charset اشتباه سرو می‌کنه.

**راه‌حل:**
1. فایل رو با UTF-8 ذخیره کن
2. دوباره آپلود کن
3. اگه PWA نصبه، از صفحه اصلی حذف کن و دوباره نصب کن

### ❌ توکن دسترسی نداره (خطای ۴۰۳)

**علت:** توکن دسترسی `Contents: Read and write` نداره.

**راه‌حل:**
1. توکن جدید بساز با دسترسی Contents
2. توکن قدیمی رو Revoke کن
3. توکن جدید رو در برنامه وارد کن

### ❌ خطا در دریافت / ذخیره

- اینترنت رو چک کن
- نام کاربری و مخزن رو بررسی کن
- توکن رو مجدد وارد کن

### ❌ داده‌ای روی GitHub نیست

اولین بار که برنامه رو باز می‌کنی، فایل `data.json` وجود نداره. با اولین **⬆️ ذخیره** ساخته می‌شه.

### ❌ PWA نصب نمیشه

- باید از **HTTPS** یا **localhost** باز بشه (نه `file://`)
- باید `manifest.json` و `sw.js` موجود باشن
- توی Chrome گوشی: منوی ⋮ → **Install app**

### ❌ نسخه قدیمی نشون داده می‌شه بعد از آپدیت

1. توی `sw.js` شماره `CACHE_NAME` رو +1 کن
2. یا توی Chrome: `F12` → **Application** → **Service Workers** → **Unregister**
3. یا کش مرورگر رو پاک کن

### ⚠️ حجم فایل نزدیک ۱ مگابایت

GitHub فایل‌های بزرگتر از ۱ مگابایت رو محدود می‌کنه.
- زیر ۴۰۰ KB: عالی
- ۴۰۰-۹۰۰ KB: هشدار (زرد)
- بالای ۹۰۰ KB: خطر (قرمز)

## 🔒 نکات امنیتی

### ✅ محافظت‌شده

- پسورد بخش پشتیبان (Base64)
- اطلاعات GitHub فقط در مرورگر
- توکن در `localStorage` (نه در فایل)

### ⚠️ محافظت‌نشده

- پسورد پشتیبان قابل دور زدن با DevTools
- توکن GitHub در `localStorage` قابل خوندنه
- اطلاعات بین مرورگرها همگام نمی‌شه (مگر با GitHub)

### 💡 توصیه‌ها

1. توکن GitHub رو امن نگه دار
2. توکن فقط با دسترسی **Contents**
3. **Expiration** توکن رو تنظیم کن
4. اگه توکن لو رفت → **Revoke** کن
5. مخزن رو **Private** کن (برای امنیت بیشتر)
6. **هر هفته** بکاپ فایلی بگیر
